# Система Поиска Нейронных Архитектур (NAS) для Food-101

Исследовательский проект, посвященный сравнительному анализу современных (SOTA) моделей компьютерного зрения и кастомных архитектур на специализированном датасете Food-101. Проект использует автоматический поиск нейронных архитектур (NAS) с помощью библиотеки `Optuna`, `PyTorch` для обучения моделей и `OmegaConf` для гибкого управления конфигурациями.

## Цель проекта

Данный проект направлен на исследование нескольких ключевых вопросов в области глубокого обучения:

### Исследовательские вопросы

**1. Эффективность transfer learning на специализированных датасетах**
- Насколько точно SOTA модели, предобученные на широких датасетах (ImageNet с 1000+ классов различных объектов), адаптируются к специализированному датасету с визуально похожими классами?
- Достаточно ли общих знаний из ImageNet для точного распознавания узкоспециализированных категорий с минимальным файнтюнингом?

**2. Обучение с нуля vs. transfer learning**
- Возможно ли создать модель с нуля, обучаясь только на специализированном датасете (в десятки раз меньше ImageNet), и достичь сравнимой с SOTA точности?
- Дают ли знания о классах, не относящихся к целевой предметной области, существенный прирост качества распознавания?

**3. Автоматический поиск оптимальной архитектуры**
- Отличительная особенность проекта — использование математически выверенного алгоритма NAS вместо эвристического подбора архитектуры. Оптимальная конфигурация модели находится путем систематического сравнения результатов на реальных данных (trial-ы Optuna), что исключает необходимость в глубоком теоретическом анализе и дает объективную картину, основанную на практических результатах, а не на теоретических предположениях.

## Результаты экспериментов

Все результаты экспериментов доступны в директории [checkpoints/](checkpoints/), включая веса моделей, метрики обучения, графики и конфигурации.

| Модель | Параметры | Точность (Val) | Эпох | Время обучения | Источник весов |
|--------|-----------|----------------|------|----------------|----------------|
| **ConvNeXt-Tiny** | 28M | **90.43%** | 30 | ~3.6 часа | ImageNet-1K |
| **ViT-Base** | 86M | **89.95%** | 30 | ~3.5 часа | ImageNet-21K |

| **Custom ViT** | 26M | **61.33%** | 80 | ~8.8 часов | С нуля (только Food-101) |

### Ключевые выводы

- **SOTA модели демонстрируют превосходство**: Предобученные модели показывают точность 83-90%, что значительно выше результатов обучения с нуля
- **Transfer learning эффективен**: Даже с минимальным файнтюнингом (30 эпох) предобученные модели достигают высокой точности на специализированном датасете
- **Обучение с нуля требует больше данных**: Custom ViT, обученная только на Food-101, достигла лишь 61% точности даже после 80 эпох, что подтверждает важность предобучения на больших датасетах
- **ConvNeXt показывает лучший результат**: Современная CNN-архитектура ConvNeXt превосходит классический ResNet-50 на 7% и немного опережает ViT-Base
- **Компактность vs. точность**: Custom ViT с 26M параметров сопоставима по размеру с ResNet-50, но существенно уступает в точности из-за отсутствия предобучения

## Основные возможности

### MLOps & Управление экспериментами

- **Гибкая система конфигурации**: Все параметры экспериментов, моделей и NAS задаются через иерархические YAML-файлы, обеспечивая воспроизводимость и версионирование экспериментов
- **Возобновляемые эксперименты**: Полная поддержка прерывания и возобновления NAS. Прогресс сохраняется в базе данных SQLite, конфигурация study автоматически персистится
- **Автоматическое логирование**: Детальные логи тренировок, метрики по эпохам, timestamped директории для каждого эксперимента
- **Checkpoint management**: Автоматическое сохранение лучших и финальных весов моделей, конфигураций и промежуточных результатов
- **Оптимизация процесса**: Автоматическое повышение приоритета процесса обучения для максимальной производительности

### Deep Learning & Neural Architecture Search

- **Двухэтапный поиск NAS с Optuna**:
  - **Stage 1 - Architecture Search**: Оптимизация структурных параметров (число слоев, heads в ViT, каналы в CNN, patch size, MLP ratio)
  - **Stage 2 - Hyperparameter Search**: Тонкая настройка learning rate, dropout, weight decay, batch size для лучшей архитектуры
- **Интеллектуальная оптимизация**: TPE (Tree-structured Parzen Estimator) sampler + Median Pruner для эффективного исследования пространства гиперпараметров
- **Комплексная оценка**: Кастомная scoring функция, учитывающая accuracy, количество параметров и время обучения
- **Поддержка архитектур**:
  - Custom Vision Transformer (ViT) с настраиваемыми параметрами
  - Custom CNN с гибкой блочной структурой
  - SOTA pretrained модели через timm (ResNet, ConvNeXt, ViT и др.)

### Data Engineering & Preprocessing

- **Продвинутые аугментации**:
  - Geometric: Random crop, horizontal flip, rotation
  - Color: Color jitter (brightness, contrast, saturation)
  - Noise: Gaussian noise injection
  - Mixing: CutMix для улучшения генерализации
- **Нормализация**: Dataset-specific mean/std calculation и применение
- **Эффективная загрузка**: PyTorch DataLoader с multi-worker support и pin_memory оптимизацией
- **Локальный датасет**: Работа с локально сохраненным Food-101, исключающая зависимость от внешних API

### Evaluation & Visualization

- **Комплексные метрики**: Accuracy, loss, per-class metrics (precision, recall, F1-score)
- **Автоматическая визуализация**:
  - Training/validation curves (loss & accuracy)
  - Confusion matrix для анализа ошибок классификации
  - Per-class metrics visualization (F1, precision, recall)
  - Box plots для распределения метрик
  - Cumulative F1-score plots
  - Scatter plots metrics взаимосвязей
- **Label persistence**: Сохранение истинных и предсказанных меток для каждой эпохи в `.npy` формате для дополнительного анализа

### Code Quality & Architecture

- **Модульная архитектура**: Четкое разделение на модули (data, models, trainer, utils, visualization)
- **Type hints & documentation**: Документированный код с типизацией
- **Гибкая расширяемость**: Легкое добавление новых моделей, метрик и аугментаций
- **Reproducibility**: Seed control для детерминированных результатов
- **Production-ready**: Gradient clipping, mixed precision готовность, scheduler support (Cosine, OneCycle, ReduceLROnPlateau)

## ▶️ Использование

### Запуск Neural Architecture Search (NAS)

NAS — это основной сценарий использования проекта.

1.  **Настройте конфигурацию**: Откройте `configs/nas_vit.yaml` или `configs/nas_cnn.yaml`. Вы можете изменить диапазоны поиска, количество `trials`, эпох на `trial` и другие параметры в секциях `architecture_search` и `hyperparameters_search`.

2.  **Запустите поиск**:
    ```bash
    python nas.py --config configs/nas_vit.yaml
    ```
    - При первом запуске будет создана база данных (например, `optuna_studies/nas_vit_custom_vit.db`) и конфигурационный файл для возобновления (например, `optuna_studies/nas_vit_custom_vit_config.yaml`).
    - Все артефакты эксперимента (логи, конфиги лучших моделей по ходу поиска) будут сохраняться в папку `checkpoints/` с меткой времени.

3.  **Возобновление поиска**: Если процесс был прерван, вы можете легко его продолжить. Просто запустите ту же команду, но укажите в качестве конфига тот, что был сохранен в `optuna_studies/`:
    ```bash
    # Увеличьте num_trials в сохраненном конфиге и запустите:
    python nas.py --config optuna_studies/nas_vit_custom_vit_config.yaml
    ```
    Скрипт автоматически обнаружит существующую базу данных и продолжит `study` с того места, где он был остановлен.

### Обучение одной модели

Вы также можете обучить конкретную модель с фиксированными параметрами, используя скрипт `train.py`.

1.  **Выберите конфигурацию**: В файле `train.py` раскомментируйте строку с нужным конфигом, например `model_cfg = OmegaConf.load("configs/custom_cnn.yaml")`.
2.  **Настройте параметры**: При необходимости измените параметры в соответствующем YAML-файле (например, количество эпох, learning rate).
3.  **Запустите обучение**:
    ```bash
    python train.py
    ```
    - Результаты (веса лучшей и последней модели, логи, графики) будут сохранены в `checkpoints/` в папке с меткой времени.

### Jupyter Ноутбуки

- `notebooks/02_visualization.ipynb`: Запустите после `train.py`, чтобы построить и изучить графики результатов обучения.

## 🔧 Конфигурация

Система использует иерархическую конфигурацию на базе `OmegaConf`.

- `base.yaml`: Содержит общие параметры, такие как настройки датасета, аугментации и базовые параметры оборудования.
- `nas_*.yaml`: Наследуют `base.yaml` и добавляют специфичные для NAS секции (`nas:`), где настраиваются параметры для `architecture_search` и `hyperparameters_search` (направления оптимизации, сэмплеры, прунеры, количество `trials` и диапазоны поиска).
- `*.yaml` (для `train.py`): Также наследуют `base.yaml` и определяют конкретную архитектуру и гиперпараметры для одного запуска обучения.
